# homework-feedback

为数学或物理的作业反馈表生成准确、简洁且有差异的学生评价。评价来自错题与题目内容，不凭空推测学生表现。

## 适用范围

- 只处理用户指定的一个学科：`数学` 或 `物理`。
- 只读取和填写同名工作表；忽略化学、英语、生物及其他工作表。
- 每位学生完成的是同一份该科作业。作业图片用于根据题号理解题目与考查知识点，不用于识别学生。
- 直接覆盖原 Excel 的目标评价单元格，不创建副本；绝不修改行高、列宽、自动换行、字体、边框或其他格式。

## 开始前收集材料

确认已具备以下材料：

1. 一个包含目标学科 sheet 的 `.xlsx` 反馈表。
2. 用户明确指定的学科（数学或物理）。若未指定，先询问本次处理哪一科。
3. 该学科整份作业的清晰图片，题号必须可见。

材料不全时，说明缺少的具体文件或信息并暂停。不要依据模糊图片、缺页图片或猜测的题目内容写入评价。

## 检查反馈表

使用本 skill 自带的 `scripts/patch_xlsx.mjs` 读取并检查工作簿；它直接解析 XLSX 内的目标工作表 XML，不导入或导出整本工作簿。为缩短处理时间，常规流程只读取目标学科 sheet 的必要区域。

1. 仅选择用户指定的 `数学` 或 `物理` sheet。
2. 在表头中定位下列精确列名：`姓名`、`课后作业错题`、`课后作业评价`。
3. 若目标 sheet 或任一必需列不存在，报告实际发现的 sheet/表头并请求用户修正；不要修改文件。
4. 仅读取学生行的姓名、错题记录和当前评价三列；保留原有行顺序与全部格式，不扫描其他 sheet。

## 题号与知识点匹配

1. 完整浏览作业图片，建立“题号 → 题目内容 → 考查知识点”的映射。
2. 当错题号采用 `P<页码>_T<题号>` 格式时，`P` 代表作业图片底部标示的页码，`T` 代表该页中的题号。先以页码定位对应图片，再以题号定位题目；例如 `P96_T1(2)` 表示第 96 页第 1 题的第（2）问。保留反馈表中的原始写法，不擅自改写题号。
3. 将每位学生“课后作业错题”中的题号与映射逐项匹配。兼容逗号、中文顿号、空格和常见题号组合写法；先按反馈表显示的题号理解，不擅自改写题号。
4. 对同一学生的所有错题归纳共同的知识薄弱点，而非逐题罗列答案。
5. 若任一需要写入的错题号在图片中找不到、题号含义不清或题目无法读清，列出姓名与具体题号，请用户补充清晰图片或说明；在问题解决前不写入该次反馈表。

## 特殊作业状态

先检查“课后作业错题”单元格是否为题号、`全对`或下列明确状态：

- `作业未交`：在“课后作业评价”中写入 `请下次记得交作业`。
- `作业未带`：在“课后作业评价”中写入 `请下次记得带作业`。
- 空白、其他文字或无法识别为题号的内容：一律跳过该学生，保留原评价不变，并在完成报告中列出跳过的姓名与原始内容。

这两类特殊状态不需要作业图片匹配，也不适用全对鼓励或 30–50 字的非全对评价规则。

## 生成评价

先为全部学生形成“姓名、错题、知识点、拟写评价”的草稿列表，再写入 Excel。

### humanizer-zh 书面化润色

在完成事实准确的草稿后，调用 `C:\Users\Lenovo\.agents\skills\humanizer-zh\SKILL.md`，对本批次需要写入的常规评价做一次**批量**语言润色；不要逐条重复调用，以免拖慢处理速度。

- 润色目标是消除套话和机械重复，让评语具体、清晰、自然，保持正式、克制的教师书面评语语气。
- 保留每位学生错题归纳出的知识点与学习建议；不得新增、删改或猜测题目事实，不得把知识性反馈改成泛泛表扬。
- 不使用第一人称、口语化表达、网络用语、夸张宣传语、空泛结论、破折号式强调或“不仅……而且……”等模板化句式。
- 润色后须重新核验字数、知识点、可执行建议、批内差异性与语气。任何一项不合格时，在内存中定向修订后再写入。
- `作业未交`、`作业未带`使用固定文本，不调用 humanizer-zh；跳过行保持原评价。全对鼓励语仅做批内自然性检查，不交给 humanizer-zh 改写，以稳定满足短句、正式和不重复的约束。

### 非全对学生

- 面向学生，采用温和、正式、具体且可执行的书面表达。
- 每条严格控制为 **30–50 个汉字**（不计常规标点）；包含一个核心知识点和一个练习或复盘建议。
- 说明具体易错点或知识环节，随后给出明确行动建议；不写分数、责备语、口语化套话或空泛评价。
- 根据学生实际错题差异分别组织知识点和建议。即使错题组合相同，也要替换开头、知识点表述或建议动词，使整条评价不完全相同。
- 批量生成时检查：任意两条非全对评价不得完全重复；避免连续使用相同开头、相同句式或相同建议动词。

### 全对学生

- 当“课后作业错题”明确为 `全对` 时，只写一句简短鼓励，不分析知识点。
- 鼓励语应尽量短（5–14 个汉字），积极自然，且同一批学生不得完全重复。
- 让同一批鼓励语的字数、开头和句式自然变化；不要让它们全部保持相同字数。
- 示例风格：`全对真棒！`、`思路清晰，表现出色！`、`这份认真值得表扬！`。仅作风格参考，不要在同批次重复使用。

## 写入与核验

1. 在写入前，先在内存中检查题号覆盖、字数、知识点与建议完整性、书面化语气和重复性；除非用户要求预览，不生成渲染图或额外展示文件。
2. 将最终文本一次性批量写入目标 sheet 的 `课后作业评价` 列中有姓名的学生行；不要新增列、行或工作表。
3. 不要调整或自动适配行高、列宽、自动换行或任何单元格格式。
4. 先调用 `node scripts/patch_xlsx.mjs inspect <文件> <学科>`，仅取得姓名、错题和评价列；据此生成并在内存中核验反馈。
5. 将 `{row, text}` 更新列表编码为 base64url JSON，再调用 `node scripts/patch_xlsx.mjs write <文件> <学科> <更新列表>`。脚本仅替换目标评价单元格 XML，并在内存中验证其他 XLSX 条目内容未变后直接覆盖原文件。
6. 不使用整本工作簿导入导出、渲染、`output.save()`、`.inspect.ndjson` 或任何临时文件；不要调整或自动适配任何格式。
7. 向用户报告已处理的学科、写入学生数、全对人数，以及因材料不足而未处理的项目（如有）。

## 执行方式

用户提交所需 Excel、学科和作业图片后，直接按本 skill 执行读取、生成和写入，不再为这些已定义的步骤请求聊天确认。若运行环境本身要求文件或网络权限，遵循环境的权限机制。

## 失败处理

- 未指定学科：询问“本次填写数学还是物理？”
- 没有作业图片：请求上传该科完整、清晰且题号可见的图片。
- 图片无法对应错题号：列出无法匹配的题号与受影响学生，请求补充；不要以通用反馈替代。
- Excel 不符合表头约定：说明缺失项并暂停，不改动原文件。
